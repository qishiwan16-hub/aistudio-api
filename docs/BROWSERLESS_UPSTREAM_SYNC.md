# 无浏览器引擎稳定性同步

参考：`Lianues/aistudio-pg-bridge`，截至提交 `90d0866`。

本次采用远程签名强制刷新、按账号分配鉴权恢复机会，以及 Cookie 会话维护。未移植上游的全状态码换号策略、代理自动探测或 Node 管理界面。

## 签名与重试

鉴权失败后，每个账号允许一次原账号恢复。无浏览器模式会向签名服务发送 `forceRefresh: true`；刷新标记按异步请求隔离，成功取得签名后消耗。连续失败的账号只在当前请求中排除，不影响其他请求的账号池。

总尝试次数至少为原来的 5 次，并随可用且符合模型权益的账号数扩展，每个账号预算两次。普通流式已经输出正文后不再重放；400、普通 404 和地区限制不触发无意义换号。原有瞬时 RPC 404 的原账号重试仍保留。

## Cookie 维护

仅 `browserless` 引擎启用后台维护。每分钟检查一次，默认同一登录会话至少间隔 420 秒，新导入 Cookie 同样等待。可通过环境变量调整：

- `AISTUDIO_BROWSERLESS_COOKIE_MAINTENANCE=0`：关闭后台维护。
- `AISTUDIO_COOKIE_ROTATION_INTERVAL=420`：轮换间隔，单位秒，最小 60。

先探测 AI Studio 登录态。明确跳转到欢迎/登录页才认定失效；限流、上游故障和网络错误保持未知，不据此封禁账号。确认登录态正常且具备轮换凭据后才调用 `RotateCookies`，轮换接口的 401 会标记同会话账号失效。

响应 Cookie 通过原子写入更新，并同步到同一登录会话的子账号。会话身份采用长效凭据的哈希，绝不使用 `u/0` 等序号关联不同登录。写入保留原 storage state、Cookie 元数据与其他字段；过期/删除值和非 Google 域 Cookie 被忽略。请求期间发生更新或重新导入时，旧响应不能覆盖新凭据或把它标记失效。

这些变更在服务下次启动后生效；更新代码不自动重启运行实例。签名服务对 `forceRefresh` 的实际支持及 Google 线上行为仍需部署后验证。
